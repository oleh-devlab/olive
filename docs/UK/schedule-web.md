# Веб-редактор розкладу

Сторінка, де власник каналу розкладу редагує таблицями свої задачі, рутини й тайм-блоки. Вхід — через Discord.

Це не окремий сервіс і не синхронізація: сервер працює всередині процесу бота (`cogs/schedule/web.py`) і пише через той самий `ScheduleProvider` у той самий `data/{user_id}_schedule.json`, що й `/task` та агент. Після кожного збереження бот одразу перераховує повідомлення з розкладом.

Увійти може лише той, у кого є канал розкладу (`/schedule_channel create`). Видалив канал — доступ до сторінки зникає одразу, не чекаючи, поки закінчиться сесія.

## Налаштування

1. **Discord developer portal** → ваш застосунок → **OAuth2**:
   - скопіюйте **Client ID** і **Client Secret**;
   - у **Redirects** додайте `<адреса сайту>/oauth/callback`, наприклад `https://olive.example.com/oauth/callback`. Адреса має збігатися до символу.
2. **`src/tokens.json`**:
   ```json
   "discord_oauth": {
       "client_id": "123456789012345678",
       "client_secret": "..."
   },
   "web_session_secret": "довгий випадковий рядок"
   ```
   `web_session_secret` підписує сесійні куки. Згенерувати: `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Без нього бот згенерує ключ сам при старті, але тоді після кожного перезапуску всім доведеться входити знову. Зміна ключа завершує всі сесії.
3. **`src/settings.py`**:
   ```python
   schedule_web_base_url = "https://olive.example.com"  # що бачить браузер
   schedule_web_host = "127.0.0.1"                      # де слухає бот
   schedule_web_port = 8080
   schedule_web_session_days = 30
   ```
   Поки `schedule_web_base_url` порожній, сервер не запускається.
4. **Доступ ззовні.** Бот слухає `host:port` по звичайному HTTP. Перед ним потрібен HTTPS: reverse proxy (Caddy, nginx) або тунель (Cloudflare Tunnel, Tailscale Funnel), що веде `schedule_web_base_url` на `127.0.0.1:8080`. Так працює і на Termux, де немає публічної IP-адреси.
   - Коли `base_url` починається з `https://`, куки позначаються `Secure` і браузер не надсилає їх по HTTP.
   - Відкривати порт напряму в інтернет без HTTPS не варто: сесійна кука піде відкритим текстом.
5. **Зберіть сторінку**: `scripts/build-web.sh`. Сторінку написано на React і TypeScript у `web/`, а те, що бот віддає з `src/static/schedule/`, збирається з неї і в git не зберігається.
   - Збірка йде в контейнері з Node, тож на хості Node не потрібен: podman, якщо він працює, інакше docker. Якщо немає жодного, скрипт бере npm хоста (Node 26 або новіший). `CONTAINER_RUNTIME=podman`, `docker` або `none` задає вибір вручну.
   - Результат не залежить від того, чим зібрано, а файли належать тому, хто запустив скрипт, — і з rootless-рантаймом, і без нього.
   - Запускайте знову після кожного `git pull`, що змінює `web/`. Без зібраної сторінки сервер не запускається, і в лозі про це написано.
6. Перезапустіть бота. Користувачі отримують посилання командою `/schedule_channel web`.

## Що на сторінці

Угорі сам розклад у вигляді календаря: один, три або сім днів поруч, лише ті години, де щось є, і лінія поточного моменту. Кожен тип записів має свій колір, тайм-блоки заштриховані, а під календарем — те, що не вмістилося. Якщо навести на запис, видно його повністю: короткому запису місця на все не вистачає.

Сторінка показує розклад, який бот порахував останнім, — той самий, що й у повідомленні в Discord, — і рахує його заново лише тоді, коли ваші дані відтоді змінилися. Тому кнопка, щоб побачити зміну, не потрібна: розклад перечитується, коли сторінка відкривається, після кожної зміни на ній і коли ви повертаєтеся на вкладку. Проте розклад починається з моменту, коли його пораховано, а сам бот перераховує його лише раз на `schedule_loop_update_seconds`; **Recalculate** просить порахувати від цієї миті, і повідомлення в Discord після цього показує вже його.

Під календарем три вкладки — Tasks, Routines, Time blocks — з однаковими таблицями:

- Подвійний клік або ✎ перетворює рядок на поля вводу. Enter зберігає, Esc скасовує.
- Рядок «+» внизу додає новий запис зі значеннями за замовчуванням, як у відповідних командах.
- ✕ видаляє запис; залежності інших записів від нього теж прибираються.
- Задачі: ⏱ записує витрачені хвилини, як `/task spend`; коли час вичерпано, задача переходить в історію.
- Рутини: ⏸ пропускає рутину до вибраної дати включно, як `/routine skip`. Редагування рядка пропуск не змінює.
- Тайм-блоки: для разового блоку вводяться дата й час, для щоденного й щотижневого — лише час доби. Кінець раніше за початок означає блок через північ.

Рядок перевіряють ті самі валідатори, що й `/task add`, `/routine add_*` і `/timeblock add`, а ліміти на кількість записів — сам провайдер, однаково для команд, агента й сайту. Збереження рядка замінює запис цілком: очищене поле (опис, дедлайн, залежності) справді очищується.

## Зміни на сторінці

```bash
cd web
npm ci
npm run watch   # перезбирає в src/static/schedule/ при кожному збереженні; оновіть сторінку в браузері
npm run lint
npm run build   # перевірка типів, потім збірка
```

Щоб у сторінки був API, бот має працювати з увімкненим веб-редактором. Workflow `Schedule Web Page` на кожен push, що зачіпає `web/`, запускає лінт і збірку та перевіряє, що npm, docker і podman збирають одну й ту саму сторінку.

## Безпека

- У Discord запитується тільки scope `identify`. Токен доступу Discord бот ніде не зберігає: він потрібен лише, щоб дізнатися id користувача.
- Сесія — це кука з HMAC-підписом (`HttpOnly`, `SameSite=Lax`). На сервері сесії не зберігаються, тому відкликати одну окрему не можна. Вихід видаляє куку в браузері, а зміна `web_session_secret` завершує всі сесії.
- Запити, що змінюють дані, приймаються лише з власного origin сайту і лише з JSON-тілом.
- Сторінка віддається зі строгим Content-Security-Policy: скрипти й стилі тільки з цього ж сервера.
